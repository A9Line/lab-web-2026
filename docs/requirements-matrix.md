# Матрица требований

Связь трёх критериев приёмки из ЛР1 с моделью данных и запросами API.

| Требование ЛР1 | Поле или сущность | Запрос | Критерий |
|----------------|-------------------|--------|----------|
| Создать объект: заведующий лабораторией создаёт заявку на вывоз отходов | `WasteRequest`, поля `title`, `laboratoryId`, `wasteTypeId`, `description` | `POST /api/waste-requests` | Критерий 1 |
| Назначить исполнителя: заведующий отдельным действием назначает инженера или подрядчика | `WasteRequest.assigneeUserId` (FK на `User`) | `PATCH /api/waste-requests/{id}/assignee` | Критерий 2 |
| Исполнитель перевёл в работу: назначенный инженер переводит свою заявку из `New` в `InProgress` | `WasteRequest.status` | `PATCH /api/waste-requests/{id}/status` | Критерий 3 |

## Пояснение

**Критерий 1** закрывается запросом `POST /api/waste-requests`. Сервер проверяет обязательные поля (`title`, `laboratoryId`, `wasteTypeId`, `description`), создаёт строку в таблице `WasteRequest`, присваивает машинный `id`, человеческий `number` и статус `New`. Клиент эти три поля не присылает.

**Критерий 2** закрывается запросом `PATCH /api/waste-requests/{id}/assignee`. В теле передаётся `assigneeUserId`. Сервер проверяет, что вызывающий пользователь имеет роль заведующего лабораторией или ответственного за экобезопасность. Статус заявки при этом остаётся `New`.

**Критерий 3** закрывается запросом `PATCH /api/waste-requests/{id}/status`. Сервер проверяет, что вызывающий пользователь — именно назначенный исполнитель этой заявки (совпадение с `assigneeUserId`). Если исполнитель другой или не назначен, возвращается 409. Допустимый переход на этом шаге: `New → InProgress`.

## Дополнительные требования

| Требование ЛР1 | Реализация в модели |
|----------------|---------------------|
| ФТ-6, ФТ-7: закрытие и отмена заявки | `PATCH …/status` со значениями `Closed` / `Cancelled` |
| ФТ-8: инженер не меняет чужую заявку | Проверка на сервере: `assigneeUserId == текущий пользователь` |
| ФТ-9: инженер не назначает себя сам | `PATCH …/assignee` доступен только ролям `LabHead` и `EcoResponsible` |
| ФТ-11: даты создания и изменения | Поля `createdAt`, `updatedAt` в `WasteRequest` |
| НФТ-1: данные сохраняются после перезапуска | Хранение в PostgreSQL |
| НФТ-3: пароли не в открытом виде | Поле `passwordHash` в `User` |
