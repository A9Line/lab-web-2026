# Заявка на тему проекта

## 1. Название и организация

**Название проекта:** Информационная система управления вывозом лабораторных отходов.

**Организация:** лабораторный комплекс образовательной организации.

Система предназначена для регистрации, обработки и контроля заявок на вывоз отходов, образующихся в лабораториях.

---

## 2. Главная сущность и справочник

**Главная сущность:** заявка на вывоз отходов.

**Справочник:** лаборатория / тип отхода.

Каждая заявка содержит ссылку на элемент справочника посредством числового идентификатора.

Основные данные заявки:

* машинный `id`;
* человеческий номер `number`;
* заголовок;
* описание;
* лаборатория;
* тип отхода;
* создатель;
* назначенный исполнитель;
* статус;
* даты создания и изменения.

---

## 3. Роли и права

| Действие                       | Заведующий лабораторией | Инженер / подрядчик | Администратор |
| ------------------------------ | ----------------------: | ------------------: | ------------: |
| Вход в систему                 |                      Да |                  Да |            Да |
| Просмотр заявок                |                      Да |                  Да |            Да |
| Создание заявки                |                      Да |                 Нет |            Да |
| Назначение исполнителя         |                      Да |                 Нет |            Да |
| Изменение статуса своей заявки |                     Нет |                  Да |            Да |
| Закрытие выполненной заявки    |                     Нет |                  Да |            Да |
| Отмена заявки                  |                      Да |                 Нет |            Да |
| Управление пользователями      |                     Нет |                 Нет |            Да |
| Управление справочником        |                     Нет |                 Нет |            Да |

Назначение исполнителя и изменение статуса являются отдельными действиями.

---

## 4. Основной сценарий

Заведующий лабораторией создаёт заявку на вывоз отходов с указанием лаборатории, типа отхода и описания, после чего ответственный пользователь назначает инженера или подрядчика исполнителем; назначенный исполнитель переводит заявку в работу, выполняет вывоз и закрывает заявку.

## 6. Что не входит в семестр

В рамках учебного семестра не планируется реализация:

* полноценного учёта нормативной документации по обращению с отходами;
* автоматического расчёта экологических платежей;
* интеграции с государственными информационными системами;
* электронного документооборота с внешними подрядчиками;
* автоматического построения маршрутов вывоза;
* полноценного бухгалтерского и финансового учёта;
* мобильного приложения.

Эти возможности могут рассматриваться как дальнейшее развитие системы.

---

## 7. Перспективы развития и ВКР

В дальнейшем систему можно расширить следующими возможностями:

1. **Расширение данных и процесса:** добавить сведения о количестве отходов, классе опасности, единицах измерения, месте временного хранения и фактической дате вывоза.

2. **Интеграция с другими системами:** реализовать обмен данными с системой учёта лабораторного оборудования и внутренней системой документооборота организации.

3. **Аналитика:** добавить отчёты по количеству и типам отходов, срокам обработки заявок и эффективности работы исполнителей.

4. **Масштабирование:** поддержать несколько лабораторных корпусов, подразделений и внешних организаций-подрядчиков.

5. **Контроль сроков:** реализовать уведомления о просроченных заявках и контроль времени обработки.

---

## 8. Отличие от аналогичных тем

Проект посвящён именно процессу управления заявками на вывоз лабораторных отходов.

Главным объектом системы является заявка на вывоз отходов, а справочниками являются лаборатории и типы отходов. В процессе участвуют заведующие лабораториями и инженеры или подрядчики.

Таким образом, проект отличается от систем ремонта оборудования, коммунальных заявок и других заявочных систем предметной областью, набором справочных данных и ролями пользователей.
