# Модель данных

## Словарь проекта

| Термин курса | Термин моей темы |
|--------------|------------------|
| Ticket       | WasteRequest — заявка на вывоз отходов |
| Site         | Laboratory — лаборатория |
| User         | User — пользователь (заведующий, инженер, эколог) |
| —            | WasteType — тип отхода (второй справочник) |

Дальше по всем документам используется термин **WasteRequest** (не Ticket, не Request).

## Сущности

### 1. WasteRequest — заявка на вывоз отходов (главный объект)

| Поле | Тип | Ключ | Описание |
|------|-----|------|----------|
| id | int | PK | машинный идентификатор |
| number | string |  | человеческий номер, например WR-2026-0001 |
| title | string |  | заголовок, 5–80 символов |
| description | string |  | описание, 10–500 символов |
| status | enum |  | `New`, `InProgress`, `Closed`, `Cancelled` |
| laboratoryId | int | FK → Laboratory.id | лаборатория |
| wasteTypeId | int | FK → WasteType.id | тип отхода |
| createdByUserId | int | FK → User.id | кто создал (заведующий) |
| assigneeUserId | int, NULL | FK → User.id | назначенный исполнитель; при создании пусто |
| createdAt | datetime |  | дата создания |
| updatedAt | datetime |  | дата последнего изменения |

### 2. Laboratory — лаборатория (справочник)

| Поле | Тип | Ключ | Описание |
|------|-----|------|----------|
| id | int | PK | машинный идентификатор |
| name | string |  | название лаборатории |

### 3. WasteType — тип отхода (справочник)

| Поле | Тип | Ключ | Описание |
|------|-----|------|----------|
| id | int | PK | машинный идентификатор |
| name | string |  | название типа отхода |
| hazardClass | int |  | класс опасности (1–5) |

### 4. User — пользователь

| Поле | Тип | Ключ | Описание |
|------|-----|------|----------|
| id | int | PK | машинный идентификатор |
| login | string |  | логин для входа |
| fullName | string |  | ФИО |
| role | enum |  | `LabHead`, `Engineer`, `EcoResponsible` |
| passwordHash | string |  | хэш пароля, не открытый пароль |

## Связи словами

- **Одна лаборатория — много заявок.** В заявке хранится только `laboratoryId`.
- **Один тип отхода — много заявок.** В заявке хранится только `wasteTypeId`.
- **Один пользователь создаёт много заявок** (поле `createdByUserId`).
- **Один пользователь может быть назначен на много заявок** (поле `assigneeUserId`).
- **У новой заявки исполнителя может не быть** — поле `assigneeUserId` допускает NULL.

## Проверка третьей нормальной формы (3НФ)

Название лаборатории хранится один раз — в сущности **Laboratory**. В заявке **WasteRequest** хранится только внешний ключ `laboratoryId`. При переименовании лаборатории меняется одна строка в справочнике, а не десятки строк в заявках.

Аналогично название типа отхода хранится один раз — в сущности **WasteType**, а в заявке только `wasteTypeId`.

ФИО пользователя хранится один раз — в сущности **User**, а в заявке только `createdByUserId` и `assigneeUserId`.

Текстовое дублирование названий справочников в главном объекте отсутствует, поэтому модель находится в 3НФ.

## Статусы и переходы

```
   ┌───────┐  инженер берёт в работу  ┌────────────┐
   │  New  │ ───────────────────────► │ InProgress │
   └───┬───┘                          └──────┬─────┘
       │                                     │
       │ заведующий отменяет                 │ инженер закрывает
       ▼                                     ▼
   ┌───────────┐                        ┌──────────┐
   │ Cancelled │                        │  Closed  │
   └───────────┘                        └──────────┘
```

- `New → InProgress` — только назначенный исполнитель.
- `InProgress → Closed` — только назначенный исполнитель.
- `New → Cancelled` — заведующий лабораторией.
- Удаление (DELETE) не используется: отмена — это статус `Cancelled`, строка остаётся в базе.
